# Espace de chat texte

[English](chat.md) | Français

M8 relie l’espace Web authentifié à PostgreSQL et à l’adaptateur de modèle texte. Il utilise les mêmes composants réutilisables que l’exemple indépendant. Cela reste un **POC expérimental, non prêt pour la production** ; pièces jointes et vision relèvent de M9.

## Utiliser l’espace

1. Démarrer Aspire comme décrit dans [l’exploitation](operations.fr.md), créer un utilisateur Keycloak et se connecter. L’hôte autonome sans PostgreSQL conserve sa page d’accueil ; l’espace indique que le stockage du chat doit être configuré.
2. Ouvrir **Connection settings**, saisir un nom de profil, l’URL de base complète de l’API joignable depuis Web et l’identifiant exact du modèle. Ne pas ajouter de chemin de version ou de port sans vérifier le serveur. La température facultative va de 0 à 2 ; le maximum de jetons de sortie doit être positif.
3. Choisir **Set or replace API key** uniquement si le serveur exige une authentification. Le choix par défaut conserve une clé existante ; un nouveau profil commence sans clé. **Remove saved key** active les requêtes anonymes. Les secrets enregistrés ne sont jamais renvoyés au navigateur. Le champ de clé est effacé après une opération.
4. Enregistrer. **Discover models** propose des identifiants si le serveur le permet ; la saisie manuelle reste disponible. Enregistrer le modèle choisi avant de tester. **Test text connection** et **Test streaming** envoient un petit prompt fixe avec les réglages enregistrés. Ces opérations peuvent consommer des ressources d’inférence locales et disposent d’un bouton d’annulation.
5. Créer une conversation nommée ou en ouvrir une dans l’historique paginé. Choisir la connexion puis envoyer du texte. **Stream response** est explicite ; un test de streaming réussi l’active. La preuve dure cinq minutes dans le circuit courant et concerne uniquement le profil/modèle/options enregistrés exacts. Après rechargement, modification ou expiration, retester le streaming ou le désactiver. Aucun test synthétique ne s’exécute automatiquement à l’envoi d’un message.
6. **Stop response** annule l’inférence et attend le nettoyage. Le texte partiel reste visible. **Reload conversation** lit l’historique durable et récupère les réponses orphelines. Les suppressions de conversation et de profil demandent une confirmation explicite dans la page. Supprimer un profil supprime aussi son secret et efface le profil sélectionné.

Le thème et la sélection de connexion sont persistés par utilisateur. L’interface utilise le modèle enregistré dans le profil et efface une surcharge de modèle distincte lors de la sélection/enregistrement d’un profil. Les pages de réglages/historique contiennent au plus 20 entrées par requête ; l’historique utilise Previous/Next et les connexions Load more. La navigation attend la fin ou l’arrêt de la réponse courante. Les brouillons et modifications de formulaire non enregistrés restent locaux au composant et ne sont pas restaurés après un rechargement complet.

Réglages et secrets sont deux écritures distinctes. Si l’écriture du secret échoue après celle des réglages, l’interface indique que les réglages du profil ont été enregistrés et affiche une erreur sûre. Ressaisir la clé et enregistrer à nouveau ; l’identifiant du profil existant est conservé. Aucun secret stocké n’est relu pour l’édition.

## Génération et persistance

`ChatService` est un orchestrateur applicatif limité à l’utilisateur, indépendant de Blazor et des bibliothèques de fournisseur/base de données. `SendAsync` accepte un identifiant de conversation possédée, un identifiant de profil possédé, un `RecordMessageRequest` stable et un choix explicite de streaming. Il autorise les deux ressources avant d’écrire la paire message utilisateur/réponse en attente. Le premier instantané émis confirme l’acceptation durable ; l’hôte efface alors le brouillon et observe la suite de l’itérateur. Il conserve l’identifiant de soumission si l’acceptation est incertaine. Une répétition identique renvoie l’historique existant sans rappeler le modèle ; une réutilisation différente du même identifiant crée un conflit.

Le modèle reçoit uniquement les paires utilisateur/assistant précédentes terminées et le nouveau message utilisateur. Les paires annulées ou échouées restent visibles dans l’historique mais sont exclues du contexte suivant. La réponse en attente n’est jamais envoyée. Aucune relance automatique, régénération ou bascule silencieuse depuis le streaming n’est implémentée.

Les deltas ordonnés du fournisseur actualisent l’écran. La persistance regroupe le texte dans un point de contrôle après 250 ms lorsqu’un nouveau delta arrive, ou après 1024 caractères. Un résultat terminal vide toujours le tampon, y compris lors d’une annulation. Chaque point de contrôle constitue une écriture atomique avec révision optimiste ; les révisions de l’agrégat immuable n’avancent pas à chaque jeton affiché. Un arrêt brutal peut perdre le texte affiché depuis le dernier point de contrôle. Le chargement/écriture de l’agrégat complet rend encore les très longs historiques coûteux ; cette conception ne vise pas des historiques illimités.

Une écriture échouée ou ambiguë n’est jamais rejouée. Le nettoyage recharge l’historique durable, conserve le texte validé et termine la réponse active sans doubler un delta incertain. Le nettoyage dispose de son propre délai de cinq secondes et revérifie l’identité courante. Si le stockage est indisponible ou la session expirée, il ne peut garantir une écriture terminale. Après rétablissement du stockage/de la session, ouvrir la conversation marque la réponse orpheline comme **interrompue**, en conservant le texte validé. Cela ne reprend jamais automatiquement une requête distante.

`GenerationRegistry` est un singleton contenant seulement des réservations/signaux d’annulation temporaires, indexés par propriétaire fiable et conversation. Il empêche les envois, récupérations et suppressions concurrents entre circuits. Charger une conversation en cours de génération ailleurs renvoie son instantané durable actuel ; **Reload conversation** l’actualise. L’arrêt depuis un autre circuit attend la libération de la réservation par l’itérateur propriétaire. Chaque itérateur doit être consommé ou libéré. Web conserve sa tâche de génération, observe ses erreurs et l’annule/attend lors de la libération du composant. Une déconnexion SignalR temporaire peut laisser un circuit conservé générer ; la reconnexion peut retrouver ce circuit, tandis qu’un nouveau circuit recharge l’état durable. Ce n’est pas un service de tâches durables en arrière-plan.

**Un seul processus Web par base est pris en charge.** Le registre n’est pas un verrou distribué. Ne pas lancer plusieurs instances Web sur la même base avec cette politique de récupération. Le stockage des sessions a déjà cette restriction. Un redémarrage du processus efface réservations et sessions ; le prochain chargement authentifié récupère toute réponse persistée encore active.

## Erreurs et frontières

Les catégories sûres conservent des actions utiles sans corps serveur ni détails d’exception bruts : indisponibilité/délai (vérifier/démarrer le serveur), requête rejetée (vérifier clé, nom du modèle, modèle chargé et options prises en charge), limite de contexte/sortie (raccourcir l’historique ou ajuster la limite), interruption (conserver le texte partiel enregistré puis envoyer explicitement un nouveau message). L’adaptateur regroupe les rejets HTTP d’authentification et de modèle indisponible ; il ne déduit pas de cause exacte depuis le texte libre d’une erreur fournisseur. Les autres erreurs comprennent l’authentification expirée, le stockage indisponible, les ressources absentes et les conflits de révision. Test/découverte utilisent le même chemin de profil autorisé et de secret protégé que la génération.

Les services applicatifs déduisent le propriétaire de l’identité fiable courante, revérifient les enregistrements renvoyés et revalident l’identité à chaque point de contrôle. `ModelConnectionService` résout un profil enregistré possédé pour les tests/découvertes. L’hôte possède la composition et la portée par utilisateur. Les composants ne référencent toujours que Contracts ; le nouveau `ChatWidget.BlockedReason` facultatif empêche l’envoi lorsque configuration/sélection sont incomplètes.

## Vérification

La suite du cœur couvre l’acceptation avant inférence, l’idempotence, le texte partiel annulé/échoué, le regroupement des points de contrôle, les commits ambigus, les capacités invalides, les profils/historiques étrangers, l’identité expirée, l’absence d’événement terminal, la libération anticipée, les circuits concurrents et la récupération. Les tests courants ne demandent ni Docker ni API payante.

Le pilote navigateur `tests/browser/workspace.mjs` est invoqué par le véritable test d’intégration Aspire avec volumes isolés, utilisateurs Keycloak temporaires et serveur HTTP de modèle contrôlé. Il vérifie deux utilisateurs, les secrets protégés, la découverte, les deux modes de réponse, l’annulation, la récupération d’erreurs, la pagination, les suppressions, le rechargement, le redémarrage complet d’AppHost, les mises en page adaptatives et axe. Installer les dépendances navigateur comme indiqué dans [le développement](development.fr.md), puis lancer :

```sh
MARMOTTE_RUN_INFRASTRUCTURE_TESTS=1 MARMOTTE_RUN_BROWSER_TESTS=1 dotnet test --project tests/Marmotte.ChatUi.Infrastructure.Tests --configuration Release --no-build --no-restore
```

Des variables facultatives ajoutent des tests de modèles réels à ce même parcours : `MARMOTTE_MODEL_ENDPOINT`, `MARMOTTE_MODEL_ID`, éventuellement `MARMOTTE_MODEL_KEY` pour LM Studio ; `MARMOTTE_UNSLOTH_ENDPOINT`, `MARMOTTE_UNSLOTH_MODEL`, éventuellement `MARMOTTE_UNSLOTH_KEY` pour Unsloth. Injecter les secrets de façon privée ; ne jamais les committer. La CI utilise uniquement le serveur contrôlé. Les captures emploient du contenu de test synthétique et se trouvent dans `tests/browser/test-results/`, ignoré par Git. La [feuille de route](../roadmap.fr.md#milestone-8) consigne la validation terminée ; la [référence modèles](models.fr.md) distingue la compatibilité réelle de la vision prévue.
